# Phase 3: Document Hub - Setup Guide

## Overview
Phase 3 implements a secure document management system with:
- Private file storage (encrypted, no public access)
- Signed URLs with 15-minute expiry (security: prevents permanent link sharing)
- Real-time sync across all users
- Full CRUD operations (Create, Read, Update, Delete)
- Category-based organization

---

## Step 1: Create the Database Table

Run this SQL in your Supabase project (Database > SQL Editor > New Query):

```sql
-- Documents metadata table
CREATE TABLE public.documents (
  id           UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  name         TEXT NOT NULL CHECK (char_length(name) > 0),
  description  TEXT CHECK (char_length(description) < 500),
  file_path    TEXT NOT NULL,
  file_size    BIGINT NOT NULL,
  mime_type    TEXT NOT NULL,
  category     TEXT NOT NULL DEFAULT 'general'
                CHECK (category IN ('general', 'policy', 'report', 'template', 'meeting')),
  uploaded_by  UUID NOT NULL REFERENCES public.profiles(id) ON DELETE SET NULL,
  created_at   TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

-- Create index for faster queries
CREATE INDEX idx_documents_uploaded_by ON public.documents(uploaded_by);
CREATE INDEX idx_documents_created_at ON public.documents(created_at DESC);

-- Enable Row Level Security
ALTER TABLE public.documents ENABLE ROW LEVEL SECURITY;

-- Policy 1: All authenticated users can READ all documents
CREATE POLICY "documents_read_all"
  ON public.documents FOR SELECT
  TO authenticated
  USING (true);

-- Policy 2: Any authenticated user can INSERT (upload) their own documents
CREATE POLICY "documents_insert_own"
  ON public.documents FOR INSERT
  TO authenticated
  WITH CHECK (auth.uid() = uploaded_by);

-- Policy 3: Users can UPDATE their own documents, or admins can update any
CREATE POLICY "documents_update"
  ON public.documents FOR UPDATE
  TO authenticated
  USING (
    auth.uid() = uploaded_by
    OR (SELECT role FROM public.profiles WHERE id = auth.uid()) = 'admin'
  );

-- Policy 4: Users can DELETE their own documents, or admins can delete any
CREATE POLICY "documents_delete"
  ON public.documents FOR DELETE
  TO authenticated
  USING (
    auth.uid() = uploaded_by
    OR (SELECT role FROM public.profiles WHERE id = auth.uid()) = 'admin'
  );
```

```sql
    'application/vnd.ms-excel',
    'application/vnd.openxmlformats-officedocument.spreadsheetml.sheet',
    'image/jpeg',
    'image/png',
    'image/webp'
  ]
);
```

**SECURITY NOTE:** `public: false` means the bucket is **PRIVATE**. Files can only be accessed via signed URLs generated by the app, not via direct public links.

## Step 3: Configure Storage Access Policies

Run these SQL commands to set up storage-level access control:

```sql
-- Policy 1: Authenticated users can READ (download) any file
CREATE POLICY "storage_authenticated_read"
  ON storage.objects FOR SELECT
  TO authenticated
  USING (bucket_id = 'documents');

-- Policy 2: Authenticated users can UPLOAD files
CREATE POLICY "storage_authenticated_insert"
  ON storage.objects FOR INSERT
  TO authenticated
  WITH CHECK (bucket_id = 'documents');

-- Policy 3: Users can only DELETE their own files
-- (Note: Supabase storage uses owner field which is set to auth.uid())
CREATE POLICY "storage_delete_own"
  ON storage.objects FOR DELETE
  TO authenticated
  USING (
    bucket_id = 'documents'
    AND auth.uid()::text = owner
  );
```

## Security Features

| Feature | Benefit |
|---------|---------|
| **Private bucket** | Files only accessible via signed URLs, never public |
| **Signed URLs** | 15-minute expiry prevents permanent link sharing |
| **RLS policies** | Database enforces access control; even admins follow rules |
| **File validation** | 50MB max, whitelist of MIME types |
| **User isolation** | Users by default see all docs but can only delete their own |
| **Audit trail** | `uploaded_by` field tracks who uploaded each file |

## How It Works (The Pattern)

This follows the **Orbit Compression Principle** from the Phase implementation document:

1. **Database row** — `documents` table stores metadata
2. **RLS policy** — `documents_read_all` controls access
3. **Realtime subscription** — Component listens for changes in real-time
4. **Storage layer** — Supabase Storage holds actual files
5. **Signed URLs** — 15-minute temporary download links

This same pattern repeats in Phases 4 (meetings), 5 (announcements), etc. Master it once, use it everywhere.

## Troubleshooting

**Upload fails with "bucket not found"?**
- Verify the SQL INSERT for the bucket succeeded
- Check Supabase Storage section to see if 'documents' bucket exists

**Can't download after uploading?**
- Ensure storage RLS policies were created
- Check browser console for errors

**Realtime sync not working?**
- Verify env vars are correct in `.env.local`
- Check Supabase project's Realtime settings are enabled

**File too large error?**
- Max is 50MB. Check your file size.
